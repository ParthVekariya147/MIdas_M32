# 11 — Smart Source Switch (બે Zoom માંથી જીવતું ચાલુ રાખવું)

## શેના માટે

કથા **Zoom થી આવે છે**. Internet ના પ્રોબ્લેમથી કોઈ વાર Zoom નો
audio + video બંધ થઈ જાય છે. એટલે **બે જુદા જોડાણ** રાખીએ છીએ:

| | ચેનલ | device | internet |
|---|---|---|---|
| **Priority 1** | Zoom | **PC** | WiFi |
| **Priority 2** | Aux 1 | **મોબાઈલ** | મોબાઈલ ડેટા (4G/5G) |

બન્નેમાં **એક જ મીટિંગ, એક જ કથા** — ફક્ત device અલગ.
એટલે એક મરે તો બીજા પર જવું, **કથા અટકવી નહીં.**

> ⚠️ મોબાઈલ **પોતાના 4G/5G** પર જ હોવો જોઈએ. એ જ WiFi પર હોય તો
> internet જાય ત્યારે બન્ને સાથે મરશે અને આખું backup નકામું.

---

## ⭐ પાયો — વિરામ vs મરેલી લાઈન

વક્તા કથામાં સહજ રીતે અટકે છે. એટલે **"અવાજ બંધ = સ્વિચ" ચાલે નહીં** —
દરેક શ્વાસે Aux ચાલુ થઈ જાય.

એટલે **ત્રણ** હાલત ગણીએ છીએ:

| હાલત | અર્થ | શું કરવું |
|---|---|---|
| 🟢 `TALKING` | `open_db` થી ઉપર **અને** લેવલ હલે છે | લાઈવ રાખો |
| 🟡 `QUIET` | ચૂપ, પણ લાઈન જીવતી | **કંઈ જ ના કરવું** |
| 🔴 `DEAD` | `dead_hold_s` સુધી સળંગ ચૂપ | **સ્વિચ કરો** |

---

## ⭐ Cross-check (આ ફીચરનું હૃદય)

એક જ વક્તા એક જ સમયે ચૂપ પણ હોય અને બોલતો પણ હોય — **અશક્ય**.

> PC-Zoom ચૂપ છે, પણ મોબાઈલ-Zoom માં અવાજ આવે છે
> → આ વિરામ **નથી**. આ **ચોક્કસ internet તૂટ્યું** છે.

| | cross-check વગર | cross-check સાથે |
|---|---|---|
| રાહ જોવી પડે | 6 s | **2 s** |
| લાઈવ પર દર | સંભળાય | લગભગ કંઈ નહીં |

કોડ: `m32_switcher.py` → `SwitchController._dead_hold_for()`

---

## ⭐ "૧-૨ dB અવાજ છે પણ કંઈ બોલતું નથી"

લાઈન મરી જાય તો પણ ઘરઘરાટ/હમ ચાલુ રહી શકે. એના માટે **બે પડ**:

### ૧. બે threshold (hysteresis)
- ચાલુ ગણવા `open_db` (**−54**) થી **ઉપર** જવું પડે
- બંધ ગણવા `close_db` (**−60**) થી **નીચે** જવું પડે

વચ્ચેના 6 dB માં લેવલ ગમે તેટલું હલે — **હાલત બદલાય જ નહીં.**

### ૨. વધઘટ (variance) — `switch_smart_noise`
હમ **સપાટ** હોય, બોલવામાં **ચઢ-ઉતાર** હોય.

| | 2 sec માં વધઘટ |
|---|---|
| મરેલી લાઈનનો હમ | < 3 dB |
| ખરેખર બોલે છે | 10-20 dB |

`flat_db` (3 dB) થી ઓછી વધઘટ = **અવાજ નથી**, ભલે લેવલ ઊંચું હોય.

કોડ: `m32_switcher.py` → `Source.wiggle()`, `Source.feed()`

## ⭐ પાછા જવામાં ધીરજ (`stable_s`)

Zoom પાછું આવે એટલે તરત સ્વિચ **નહીં** — ફરી તૂટે તો?

- `stable_s` સુધી **સળંગ જીવતી** રહે તો જ પાછા જવું
- વચ્ચે એક વાર પણ મરે → **ટાઈમર ફરી 0:00 થી**
- સમય **મિનિટ + સેકન્ડ** બન્નેથી પસંદ થાય (default **3 મિ 00 સે**)
- સ્ક્રીન પર ગણતરી દેખાય + **"હમણાં જ સ્વિચ કરો"** થી કૂદાવી શકાય

**છટકબારી:** રાહ જોતા હોઈએ ત્યાં Aux **પણ** મરી જાય → તરત Zoom પર પાછા
(ટાઈમર ગણવાનો જ નહીં).

## ⭐ SYNC — બે Zoom વચ્ચે સમયનો ફરક

PC અને મોબાઈલનું Zoom **0.5-3 સેકન્ડ આગળ-પાછળ** હોય છે.
સ્વિચ કરતાં શબ્દ બે વાર સંભળાય કે કપાઈ જાય.

**ઉકેલ — વિરામમાં જ સ્વિચ કરવું** (`switch_at_pause`):

| સ્વિચ | ક્યારે | સંભળાય? |
|---|---|---|
| Zoom → Aux | લાઈન મરેલી છે = ત્યાં શાંતિ જ છે | ના ✅ |
| Aux → Zoom | `stable_s` પછી, **પહેલા વિરામની રાહ જોઈને** | ના ✅ |

વિરામ ના મળે તો `pause_wait_s` (20 s) પછી crossfade થી કરી દે.

## ⭐ સ્ટીરિયો પેર — એક source માં ઘણી channel

"Photo Video" ડેસ્ક પર **બે channel** પર છે — CH 31 (L) અને CH 32 (R).
**બન્ને mute થવા જોઈએ**, નહીં તો એક બાજુ ચાલુ રહી જાય.

એટલે દરેક source માં **ઘણી channel** રાખી શકાય:

| | શું |
|---|---|
| `indexes` | કઈ કઈ સાંભળવી — **જેમાં મોટો અવાજ હોય તે ગણાય** |
| `targets` | કઈ કઈ mute/unmute કરવી — **બધી જ** |
| `faders` | crossfade માં **બધા** fader સાથે ખસે |

```json
{ "name": "Photo Video (CH 31+32)",
  "indexes": [30, 31],
  "targets": ["/ch/31/mix/on", "/ch/32/mix/on"],
  "faders":  ["/ch/31/mix/fader", "/ch/32/mix/fader"] }
```

GUI માં **SAMBHALVU** કે **CONTROL KARVU** નું બટન દબાવો → જેટલી જોઈએ
તેટલી tick કરો. ઉપર શોધવાનું ખાનું પણ છે.

**"NAAM parthi jate gothvo"** બટન — એક જ નામની બે channel (દા.ત.
બન્ને "Photo Video") હોય તો **જાતે ભેગી કરીને એક source** બનાવે છે.

> જૂની `"index": 30` વાળી config પણ ચાલે છે — બદલવાની જરૂર નથી.

## ⚠️ કોડમાં યાદ રાખવા જેવું

### ૧. કાચો લેવલ જ વાપરવો
```python
self.switcher.feed(self.all_levels[:n_all], ...)   # સાચું — કાચો લેવલ
# self.levels_eff  ← ખોટું!
```
`all_levels` = આખા bank ના ૭૦ લેવલ, એટલે source માં CH 1-32 ઉપરાંત
Aux In / FX Return / Bus / Matrix પણ ચાલે. `[:n_all]` = મિક્સરે ખરેખર
જેટલી value આપી હોય તેટલી જ — બાકીના index "ખબર નથી" રહે, "−128 = લાઈન
મરી" ના ગણાય.
`levels_eff` માં mute કરેલી ચેનલ **−128** બતાવે છે. Backup ને આપણે
જ mute કરીએ છીએ — એટલે `levels_eff` વાપરીએ તો **"backup મરી ગયું"**
લાગે અને ક્યારેય પાછું સ્વિચ ના થાય.
(`m32_engine.py:211` — `ch_on == 0` → `gain = None` → `−128`)

### ૨. `time.monotonic()` વાપરવો, `time.time()` નહીં
૩ કલાકની કથામાં Windows નો NTP ટાઈમ કૂદે તો ૩ મિનિટનો ટાઈમર ખોટો
ગણાય. `monotonic` કદી પાછળ જતું નથી.

### ૩. Make-before-break
પહેલા **નવું ચાલુ**, `overlap_ms` પછી **જૂનું બંધ**.
વચ્ચે એક પણ ક્ષણ માટે અવાજ બંધ થતો નથી.
કોડ: `m32_engine.py` → `_switch_apply()`
