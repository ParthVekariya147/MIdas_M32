## ૧. એક નજરમાં — આખી સિસ્ટમ શું કરે છે

```
  મિક્સર (MIDAS M32)                         આ પ્રોગ્રામ (PC)
  ------------------                         ----------------
                      ---- મીટર (દર ~50ms) --->  અવાજ કેટલો છે?
   /meters/0  (૭૦ value)                        ફેડર/મ્યુટ ધ્યાનમાં લો
                      <--- OSC command -----     ખરો લેવલ નક્કી કરો
   /config/mute/5                                      |
   /dca/8/fader                              +---------+---------+
   /ch/09/mix/on                             |                   |
                                        Auto FX Mute      Smart Switch
                                      (અવાજ -> ઇફેક્ટ)   (લાઈન મરે -> સ્વિચ)
```

બે સાવ **અલગ** કામ, એક જ પ્રોગ્રામમાં, બન્ને અલગ અલગ ચાલુ/બંધ થાય:

| | ફીચર | શેના માટે | GUI માં ક્યાં |
|---|---|---|---|
| **૧** | **Auto FX Mute** | ગાવાનું બંધ થાય → Reverb/Delay બંધ (ગુંજન/વ્હીસલ ના થાય) | Tab 1 |
| **૨** | **Smart Source Switch** | Zoom નું internet તૂટે → મોબાઈલવાળી લાઈન પર જાતે જવું | Tab 2 |

## ૨. ફાઈલોનો નકશો — કયું લોજિક ક્યાં છે

```
m32_app.py            <- બધું અહીંથી ચાલુ (exe આમાંથી જ બને)
  |-- m32_gui.py          સ્ક્રીનવાળું UI (૨ tab, બધા toggle)
  |-- m32_automation.py   CMD વાળું (સ્ક્રીન પર બતાવે)
  |     \-- m32_engine.py      * આખું મગજ — GUI/CMD બન્ને આ જ વાપરે,
  |     |                        અને automation.log પણ આ જ લખે
  |           |-- m32_switcher.py   Smart Switch નું અલગ મગજ (મિક્સર વગર ચાલે)
  |           \-- m32_core.py       જોડાણ, dB ગણિત, FEATURES, targets, config
  |                 \-- osc_lite.py    મિક્સરની ભાષા (OSC) — કોઈ library નહીં
  |-- find_mixer.py       નેટવર્કમાં મિક્સર શોધવું
  |-- channel_select.py   ચેનલ જાતે પસંદ કરવી
  |-- meter_scan.py       બોલો એટલે ચેનલ જાતે શોધે
  |-- test_fx.py          target ૩ વાર on/off કરી ચકાસે
  |-- m32_simulator.py    નકલી M32 (મિક્સર વગર કામ)
  \-- test_all.py         ૧૦૬ આપોઆપ ટેસ્ટ
```

**સૌથી અગત્યનો નિયમ:** લોજિક **ફક્ત `m32_engine.py`** માં લખવું.
GUI અને CMD બન્ને એ જ વાપરે છે — એક જગ્યાએ સુધારો, બન્નેમાં અસર.

## ૩. બધા ૧૫ TOGGLE — એક ટેબલમાં

બધા `m32_core.py` → `FEATURES` માં છે. GUI ના toggle એમાંથી **જાતે** બને છે
(નવું ઉમેરો તો UI માં આપોઆપ દેખાય). બધાની હાલત `config.json` →
`"features"` માં સેવ થાય. **ચાલુ હાલતમાં પણ બદલી શકાય — restart નહીં.**

| # | key | નામ | default | શું કરે |
|---|---|---|---|---|
| ૧ | `auto_fx` | Auto FX Mute | **ચાલુ** | અવાજ પ્રમાણે target ચાલુ/બંધ |
| ૨ | `respect_fader` | Fader / Mute ધ્યાનમાં લો | **ચાલુ** | ફેડર નીચે / મ્યુટ હોય તો એ માઈક ના ગણવો |
| ૩ | `fader_boost` | Fader જાતે 0 dB પર | બંધ | unmute → 0 dB, mute → જ્યાં હતો ત્યાં |
| ૪ | `auto_switch` | Smart Source Switch | બંધ | લાઈન મરે તો બીજી source પર જવું |
| ૫ | `switch_cross_check` | બીજી લાઈન સાથે સરખાવો | **ચાલુ** | એક ચૂપ + બીજી બોલે → વિરામ નથી, લાઈન તૂટી |
| ૬ | `switch_smart_noise` | હમ અને અવાજ ઓળખો | **ચાલુ** | સપાટ ઘરઘરાટને "અવાજ" ના ગણવો |
| ૭ | `switch_stability` | પાછા જતાં સ્થિરતા ચકાસો | **ચાલુ** | ઉપરની લાઈન સ્થિર થાય પછી જ પાછા |
| ૮ | `switch_at_pause` | વિરામમાં જ સ્વિચ કરો | **ચાલુ** | બે Zoom નો સમયનો ફરક ના સંભળાય |
| ૯ | `switch_watchdog` | ડેટા બંધ → freeze | **ચાલુ** | મીટર ના આવે તો સ્વિચ કરવું જ નહીં |
| ૧૦ | `safe_mode` | Safe Mode (test) | બંધ | મિક્સરને **એક પણ** command ના મોકલે |
| ૧૧ | `start_muted` | શરૂઆતમાં mute | **ચાલુ** | ચાલુ કરો ત્યારે target બંધ કરી દે |
| ૧૨ | `mute_on_exit` | બંધ કરતાં mute | **ચાલુ** | પ્રોગ્રામ બંધ થાય ત્યારે target બંધ |
| ૧૩ | `auto_reconnect` | જાતે ફરી જોડો | **ચાલુ** | ડેટા બંધ થાય તો ફરી subscribe કરે |
| ૧૪ | `logging` | Log file લખો | **ચાલુ** | `automation.log` માં સાચવે — **GUI અને CMD બન્નેમાં**. બંધ કરો તો ફક્ત સ્ક્રીન પર |
| ૧૫ | `show_meter` | મીટર બતાવો | **ચાલુ** | સ્ક્રીન પર level bar |

**જૂની config પણ ચાલે:** `get_feature()` પહેલાં `features` માં જુએ, ના મળે
તો config ના મૂળ level પર (`start_muted` સીધું લખેલું હોય તો પણ ચાલે),
ના મળે તો `FEATURES` નો default.

## ૪. ફીચર ૧ — AUTO FX MUTE (મુખ્ય ફીચર)

### કઈ રીતે કામ કરે

```
મીટર આવ્યું -> દરેક ચેનલનો dB -> ફેડર/મ્યુટ લગાવો -> પસંદ કરેલી ચેનલોમાંથી
સૌથી મોટો લેવલ -> threshold સાથે સરખાવો -> નિર્ણય
```

### લોજિકના નિયમ (`m32_engine.py` → `_update()`)

| શરત | શું થાય |
|---|---|
| `auto_fx` બંધ છે | **કંઈ જ ના બદલાય** (ફક્ત મીટર દેખાય) |
| `level_db > threshold_db` | અવાજ છે — ટાઈમર શરૂ |
| અવાજ `attack_time` સુધી સળંગ | **FX ચાલુ** (unmute) |
| શાંતિ `hold_time` થી વધારે | **FX બંધ** (mute) |
| વચ્ચે એક વાર અવાજ આવ્યો | hold નો ટાઈમર **ફરી શરૂ** |

- **કોઈ પણ એક** પસંદ કરેલી ચેનલમાં અવાજ → ઇફેક્ટ ચાલુ (OR લોજિક)
- **બધી જ** ચેનલ શાંત → hold પછી બંધ
- `fx_on` પહેલેથી જે હાલતમાં હોય તે **ફરી ના મોકલે** (નકામા command નહીં)

### ડિફોલ્ટ આંકડા

| સેટિંગ | default | અર્થ |
|---|---|---|
| `threshold_db` | **−40 dB** | આથી ઉપર = અવાજ છે |
| `hold_time` | **1.5 સેકન્ડ** | શાંતિ પછી આટલી વાર રાહ, પછી બંધ |
| `attack_time` | **0.02 સેકન્ડ** | આટલો અવાજ સળંગ હોય તો જ ચાલુ |
| `meter_bank` | **0** | કયું મીટર bank |

### મર્યાદા

- threshold **એક જ** છે (hysteresis નથી) — બરાબર −40 ની આસપાસ અવાજ હોય
  તો ઝબકી શકે. (Smart Switch માં બે threshold છે, અહીં નથી.)
- બધી પસંદ કરેલી ચેનલ માટે **એક જ** threshold — per-channel નથી.
- એક જ નિયમ — "CH 1 → FX 1, CH 5 → FX 2" જેવા **અલગ અલગ નિયમ નથી** (F2).

## ૫. ફીચર ૨ — FADER / MUTE ધ્યાનમાં લેવું (R10)

### કેમ જોઈએ

મિક્સરનું **bank 0 નું મીટર PRE-FADER છે** — ફેડર સાવ નીચે હોય તો પણ
મીટર હલે છે. એટલે ફેડર નીચે હોય તો પણ ઇફેક્ટ ચાલુ થઈ જતી હતી
(**આ બગ ખરા મિક્સર પર CH 10 પર પકડાયો હતો**).

### ફોર્મ્યુલા

```
ખરો લેવલ  =  મીટરનો dB  +  ચેનલના ફેડરનો dB  +  તેના DCA ના ફેડરનો dB
```

### ચેનલ સાવ ના ગણવાની ૪ શરતો (`channel_gain_db()` → `None`)

| # | શરત | OSC |
|---|---|---|
| ૧ | મિક્સરે આ ચેનલની માહિતી **હજી આપી જ નથી** | — (સલામતી) |
| ૨ | ચેનલ **મ્યુટ** છે | `/ch/XX/mix/on` = 0 |
| ૩ | તેનું **mute group ચાલુ** છે | `/ch/XX/grp/mute` + `/config/mute/N` |
| ૪ | તેનું **DCA બંધ** છે | `/ch/XX/grp/dca` + `/dca/N/on` |

> **નિયમ ૧ બહુ અગત્યનો છે:** ખબર ના પડે ત્યાં સુધી **"બંધ છે" માનવું**.
> પહેલાં "unity છે" માની લેતું હતું, એટલે શરૂઆતની અડધી સેકન્ડમાં ખોટો
> trigger થઈ શકતો હતો (race condition). હવે એ નથી.

### મિક્સર જવાબ ના આપે તો

**૪ સેકન્ડ** રાહ જુએ. પછી `_state_gaveup = True` → "ફેડર ધ્યાનમાં લીધા
વગર" જૂની રીતે ચાલુ રાખે, અને log માં ચેતવણી લખે. (જૂનું firmware કે
બીજો desk હોય તો પણ પ્રોગ્રામ અટકે નહીં.)

### કેટલી વાર પૂછે

| શું | કેટલી વાર |
|---|---|
| પસંદ કરેલી ચેનલનાં fader/mute/DCA | દર **૨ સેકન્ડ** |
| DCA + mute group ની હાલત | દર **૨ સેકન્ડ** |
| બધી ૩૨ ચેનલ | દર **૧૫ સેકન્ડ** |
| `/meters` subscription ફરી | દર **૪ સેકન્ડ** (X32 નું ૧૦ સેકન્ડમાં expire થાય) |

(`/xremote` થી મિક્સર જાતે પણ બદલાવ મોકલે છે — આ પૂછવું એ **safety net** છે.)

### ફેડર → dB (મિક્સરની પોતાની ગણતરી, `fader_to_db()`)

| fader | dB | | fader | dB |
|---|---|---|---|---|
| 1.00 | +10 | | 0.25 | −30 |
| 0.75 | **0 (unity)** | | 0.0625 | −60 |
| 0.50 | −10 | | 0.00 | −90 (−∞) |

`db_to_fader()` એનાથી ઊંધું (R12 માટે જરૂરી). GUI માં દરેક ચેનલનો
`+0.0` / `−10.5` / `-oo` / `MUTE` ખાનો આ જ ગણતરીથી દેખાય છે.

### મર્યાદા

- ત્રણ યાદી છે: `all_levels` = આખા bank નો કાચો લેવલ (૭૦), `levels` =
  ૩૨ ચેનલનો કાચો, `levels_eff` = ફેડર લગાવ્યા પછીનો. **Auto FX
  `levels_eff` વાપરે, Smart Switch `all_levels` (કાચો) વાપરે** — કેમ, તે §૬ માં.
- **Bus/Aux send નું level જોતું નથી** — ચેનલ FX bus પર મોકલે છે કે નહીં
  તે ખબર નથી પડતી (F6 બાકી).
- ફક્ત **ચેનલ** (`/ch/`) ના fader/mute/DCA જુએ છે. Aux In / FX Return /
  Bus ની ફેડર-મ્યુટ હાલત નથી જોતું.

## ૬. ફીચર ૩ — SMART SOURCE SWITCH (R11, બે Zoom)

### સેટઅપ

| | ચેનલ | device | internet |
|---|---|---|---|
| **Priority 1** | Zoom | PC | WiFi |
| **Priority 2** | Aux 1 | મોબાઈલ | મોબાઈલ ડેટા (4G/5G) |

યાદીની **ગોઠવણ = priority** (ઉપરવાળી પહેલી). બન્નેમાં એક જ મીટિંગ,
એક જ કથા — ફક્ત device અલગ.

> ⚠️ મોબાઈલ **પોતાના 4G/5G** પર જ હોવો જોઈએ. એ જ WiFi પર હોય તો internet
> જાય ત્યારે **બન્ને સાથે મરશે** અને આખું backup નકામું.

### પાયો — ત્રણ હાલત (વિરામ vs મરેલી લાઈન)

વક્તા કથામાં સહજ રીતે અટકે છે. એટલે **"અવાજ બંધ = સ્વિચ" ચાલે નહીં** —
દરેક શ્વાસે Aux ચાલુ થઈ જાય.

| હાલત | કોડમાં | અર્થ | શું કરવું |
|---|---|---|---|
| 🟢 બોલે છે | `TALKING` | અવાજ છે | લાઈવ રાખો |
| 🟡 અટક્યા | `QUIET` | ચૂપ, પણ લાઈન જીવતી | **કંઈ જ ના કરવું** |
| 🔴 લાઈન મરી | `DEAD` | આટલી વાર સળંગ ચૂપ | **સ્વિચ કરો** |

### "અવાજ છે" કેમ નક્કી થાય — બે તાળાં

**૧) બે threshold (hysteresis)**

```
      −54 dB  --------  આથી ઉપર જાય તો જ "અવાજ ચાલુ"   (open_db)
                 ^  આ ૬ dB વચ્ચે ગમે તેટલું હલે -> હાલત બદલાય નહીં
      −60 dB  --------  આથી નીચે જાય તો જ "અવાજ બંધ"    (close_db)
```

**૨) વધઘટ (variance) — `switch_smart_noise`**

> "૧-૨ dB અવાજ છે પણ કંઈ બોલતું નથી" વાળો પ્રશ્ન અહીં પતે છે.

છેલ્લાં **૨ સેકન્ડ** માં લેવલ કેટલું ઉપર-નીચે થયું (`wiggle`)?

| વધઘટ | અર્થ |
|---|---|
| < **૩ dB** (સપાટ) | હમ / ઘરઘરાટ → **અવાજ નથી** (લેવલ ઊંચું હોય તો પણ) |
| ૧૦-૨૦ dB | ખરેખર બોલવું (શબ્દો, વિરામ) → અવાજ છે |

- હજી **૩ થી ઓછા** sample હોય, કે **0.5 સેકન્ડ** થી ઓછો ઇતિહાસ હોય, તો
  `wiggle` = **99** ("ખબર નથી") — શરૂઆતના બે-ત્રણ sample પર ખોટો નિર્ણય ના થાય.
- આ નિયમ **ચાલુ હોય ત્યારે પણ** લાગે છે: લેવલ ઊંચું હોય પણ સપાટ થઈ જાય
  (Zoom મર્યા પછી હમ ચાલુ રહે) → "અવાજ બંધ".

### ⭐ CROSS-CHECK — આ ફીચરનું હૃદય

એક જ વક્તા એક જ સમયે ચૂપ પણ હોય અને બોલતો પણ હોય — **અશક્ય**.
PC-Zoom ચૂપ **પણ** મોબાઈલ-Zoom બોલે → વિરામ નથી, **internet તૂટ્યું**.

| | રાહ |
|---|---|
| એકલું (cross-check ના મળે) | **૬ સેકન્ડ** (`dead_hold_s`) |
| **Cross-check મળે** | **૨ સેકન્ડ** (`cross_dead_hold_s`) |

Cross-check ગણાય તેની શરતો:
1. બીજી source **ચાલુ** (`on`) હોય અને તેનો `alive` હોય
2. તેનો લેવલ `open_db + 6 dB` **થી ઉપર** હોય — હલકો bleed ના ગણાય
   (`bleed_guard_db`)
3. તે **૧ સેકન્ડ** થી સળંગ બોલતી હોય (`cross_confirm_s`)

### પાછા જવામાં ધીરજ — `switch_stability`

- ઉપરની priority **`stable_s` સુધી સળંગ જીવતી** રહે તો જ પાછા જવું —
  default **૧૮૦ સેકન્ડ = ૩ મિનિટ**
- વચ્ચે **એક વાર પણ** `DEAD` થાય → ટાઈમર **ફરી 0:00 થી**
  (`stable_since = None`)
- GUI માં ગણતરી દેખાય + **"હમણાં જ સ્વિચ કરો"** બટનથી કૂદાવી શકાય
- સમય **મિનિટ + સેકન્ડ** બન્નેથી પસંદ થાય

### વિરામમાં જ સ્વિચ — `switch_at_pause` (SYNC નો ઉકેલ)

PC અને મોબાઈલનું Zoom **0.5-3 સેકન્ડ** આગળ-પાછળ હોય છે. બન્ને સ્વિચ
શાંતિમાં થાય એટલે ફરક સંભળાય નહીં.

- સ્થિર થઈ ગયા પછી **વિરામની રાહ** જુએ
- પણ **૨૦ સેકન્ડ** (`pause_wait_s`) થી વધારે નહીં — પછી બોલતાં બોલતાં પણ સ્વિચ

### `tick()` નો **નિર્ણયનો ક્રમ** (આ જ ક્રમમાં ચકાસાય છે)

```
૧.  બધી source ની હાલત નક્કી કરો (settle)   <- હંમેશા, toggle બંધ હોય તો પણ
૨.  auto_switch બંધ?                       -> કંઈ નહીં
૩.  ૨ થી ઓછી ચાલુ source / બે એક જ index?  -> કંઈ નહીં + log ચેતવણી
૪.  મીટર ડેટા 1.5 સેકન્ડ થી બંધ?            -> FREEZE, કંઈ નહીં
૫.  એન્જિનિયરે HOLD કર્યું?                 -> કંઈ નહીં
૬.  હજી કોઈ લાઈવ નથી?                      -> જે ઉપરની જીવતી હોય તે ખોલો
૭.  લાઈવ લાઈન DEAD?                        -> તરત નીચેની priority પર
                                              (min_dwell ૧ સેકન્ડ સુધી ઘટે)
૮.  ઉપરની priority પાછી આવી?               -> સ્થિરતા (૩ મિ) -> min_dwell (૫ સે)
                                              -> વિરામ -> સ્વિચ
૯.  બીજું કંઈ નહીં                          -> કંઈ ના કરવું
```

### બીજા બધા નિયમો

| નિયમ | કેમ / વિગત |
|---|---|
| **બન્ને ચૂપ → કંઈ નહીં** | જે લાઈવ છે એ જ રહે. **કદી બધું mute નહીં** |
| **૨ થી ઓછી source → toggle ચાલે જ નહીં** | GUI માં ગ્રે + કારણ બતાવે |
| **બે source એક જ index સાંભળે → ના ચાલે** | ભૂલ પકડાય |
| **ડેટા બંધ → freeze** | મીટર ના આવે તો હાલત જેમ છે તેમ (ખોટો સ્વિચ નહીં) |
| **માણસ સામે લડવું નહીં** | HOLD → auto થંભી જાય |
| **MAKE-BEFORE-BREAK** | **પહેલાં નવું ચાલુ, ૧૫૦ms પછી જૂનું બંધ** — વચ્ચે એક ક્ષણ પણ અવાજ બંધ ના થાય |
| **crossfade ૨૫૦ms** | ફેડરથી smooth, click ના થાય |
| **કાચો લેવલ વાપરવો** | `levels`, **`levels_eff` નહીં** — નહીં તો આપણે જ mute કરેલી backup "મરેલી" લાગે (આ અસલી બગ હતો) |
| **`time.monotonic()`** | ૩ કલાકની કથામાં Windows નો clock કૂદે તો ૩ મિનિટનો ટાઈમર ખોટો ના પડે |
| **min_dwell ૫ સેકન્ડ** | ping-pong અટકાવવા. પણ emergency માં **૧ સેકન્ડ** |
| **સોર્સ ગમે ત્યારે બદલાય** | આજે CH 9, કાલે Aux 3 — બધું editable, એક વાર save |
| **settings બદલો તો ટાઈમર ના તૂટે** | `configure()` જૂની હાલત (hist, timer) સાચવી રાખે — જો નામ અને index એ જ હોય |
| **stereo pair** | એક source માં ઘણા index (મોટો ગણાય) અને ઘણા target (બન્ને mute થાય) |

## ૭. ફીચર ૪ — FADER જાતે 0 dB પર, પાછું જ્યાં હતું ત્યાં (R12)

```
   fader −20 dB
        |
        |-- અનમ્યુટ થયું  ->  fader   0 dB     (જૂનું −20 યાદ રાખ્યું)
        |
        \-- મ્યુટ થયું    ->  fader −20 dB     (પાછું ત્યાં જ)
```

### લોજિક

| ક્યારે | શરત | શું થાય |
|---|---|---|
| **અનમ્યુટ** | fader `to_db − tolerance` **થી ઉપર** છે | **કંઈ જ ના કરવું** (યાદ પણ ના રાખવું) |
| **અનમ્યુટ** | નીચે છે | અત્યારનું value **યાદ રાખો**, પછી `to_db` પર ramp |
| **મ્યુટ** | કંઈ યાદ રાખ્યું જ નથી | કંઈ નહીં |
| **મ્યુટ** | એન્જિનિયરે વચ્ચે **હાથથી બદલ્યું** (ફરક > 0.02) | **પાછો ના લઈ જવો** + log |
| **મ્યુટ** | બાકી | યાદ રાખેલા value પર ramp |

### સેટિંગ્સ

| નામ | default | શું કરે |
|---|---|---|
| `target` | `/dca/8/fader` | કયો fader |
| `to_db` | **0.0** | ક્યાં સુધી લઈ જવો |
| `tolerance_db` | **1.0** | આટલાની અંદર હોય તો **હાથ જ ના લગાવો** |
| `ramp_ms` | **250** | ધીમે ધીમે (click ના થાય) |

**`_note_fader()` — એક આડો પણ જરૂરી ભાગ:** આપણે જે fader મોકલીએ તે આપણી
પોતાની યાદીમાં પણ લખી દેવું. નહીં તો આપણે 0 dB મોકલ્યું હોય અને યાદીમાં
જૂનું −20 હોય, એટલે પછી "એન્જિનિયરે હાથથી બદલ્યું" એવું **ખોટું** લાગે.
(આ અસલી બગ હતો, ટેસ્ટમાં પકડાયો.)

### મર્યાદા

- `target` ફક્ત **`/dca/N/fader`** કે **`/ch/NN/mix/fader`** ચાલે. Bus,
  Matrix, Main નો fader આપો તો `_fader_now()` પાસે તેનું value નથી, એટલે
  **ચૂપચાપ કંઈ નહીં થાય** (error પણ નહીં). GUI નું dropdown પણ આ બે જ બતાવે.
- **એક જ** fader — ઘણા fader એકસાથે નહીં.
- `active` ચાલુ હોય **અને** `safe_mode` બંધ હોય તો જ કંઈ થાય.
- મિક્સરે તે fader નું value આપ્યું ના હોય તો કંઈ ના થાય.

| બીજા બધા (`/ch/`, `/fxrtn/`, `/dca/`…) | **ચાલુ** = અવાજ ચાલુ | **1** |

`invert: "auto"` (default) હોય તો `/config/mute/` વાળા બધા **જાતે** ઊંધા
થઈ જાય. વાપરનારે વિચારવું ના પડે. `true`/`false` લખીને જબરજસ્તી પણ કરાય.

## ૯. ફીચર ૬ — કઈ ચેનલ સાંભળવી

### મીટર નકશો (bank 0 માં ૭૦ value — ખરા M32 firmware 4.13 પર માપેલું)

| index | શું |
|---|---|
| 0-31 | CH 1-32 |
| 32-39 | Aux In 1-8 |
| 40-47 | FX Return 1-8 |
| 48-63 | Bus 1-16 |
| 64-69 | Matrix 1-6 |

### બે રીતે પસંદ થાય

1. **જાતે** — ચેનલ નંબર લખીને / GUI માં tick કરીને
2. **આપોઆપ** — `scan` : માઈકમાં બોલો એટલે ચેનલ જાતે શોધે

`meter_index` ત્રણેય રીતે લખાય: `0` / `[0, 1, 4]` / `"0,1,4"` —
`parse_indexes()` બધું list માં ફેરવી દે (ખોટું હોય તો `[0]`).

### મર્યાદા

- **Auto FX માટે GUI માં ફક્ત CH 1-32** પસંદ થાય. `config.json` ના
  `meter_index` માં ૩૨ થી મોટો index લખો તો તે પણ ચાલે છે — પણ ત્યાં
  **કાચો લેવલ** વપરાય (તેના ફેડર/મ્યુટ ની ખબર પડતી નથી).
- પસંદ કરેલો index bank માં ના હોય તો log માં ચેતવણી આવે, નિર્ણય ના થાય.
- ચેનલનાં નામ મિક્સર પાસેથી વંચાય છે — મિક્સર જવાબ ના આપે તો ખાલી રહે.

## ૧૦. ફીચર ૭ — લાઈવ પ્રોગ્રામમાં સલામતી

| રક્ષણ | કઈ રીતે |
|---|---|
| **GUI ખોલો → મિક્સર પર કંઈ ના થાય** | `active = False`. મીટર દેખાય, command ના જાય |
| **મોટું toggle ચાલુ કરો ત્યારે જ** | `set_active(True)` પછી જ command |
| **Safe Mode** | `_can_send()` ખોટું → **એક પણ** command ના જાય, log માં `[SAFE MODE]` |
| **શરૂઆતમાં mute** | ચાલુ કરતાં જ target બંધ (`start_muted`) |
| **બંધ કરતાં mute** | પ્રોગ્રામ બંધ થાય ત્યારે target બંધ (`mute_on_exit`) |
| **હાથથી ઓવરરાઈડ** | એન્જિનિયર ગમે ત્યારે મિક્સર પર જાતે બદલી શકે |
| **`--dry-run`** | `safe_mode` જાતે ચાલુ થઈ જાય |

**`_can_send()` નો એક જ નિયમ** — બધે આ જ વપરાય છે:
```
command જશે   <=>   active ચાલુ  અને  safe_mode બંધ  અને  mixer જોડાયેલું
```

## ૧૧. ફીચર ૮ — જોડાણ (OSC) અને ટકી રહેવું

| | |
|---|---|
| protocol | **UDP OSC**, port **10023** |
| library | **કોઈ pip library નહીં** — ફક્ત Python સાથે આવતું (`osc_lite.py`) |
| socket | **એક જ** — send અને receive બન્ને (X32 એ જ port પર જવાબ મોકલે) |
| શોધવું | broadcast `/info` થી નેટવર્કમાં જાતે મળે |
| subscription | `/meters/0` + `/xremote`, દર **૪ સેકન્ડ** ફરી (૧૦ માં expire) |
| ડેટા બંધ | **૩ સેકન્ડ** કંઈ ના આવે → ચેતવણી + (`auto_reconnect` ચાલુ હોય તો) ફરી subscribe |
| socket | **non-blocking** — level check ધીમું ના પડે |
| મીટર → dB | `to_db()` : 0.0-1.0 (linear) અને સીધો dB — **બન્ને જાતે સંભાળે** |
| loop | દર ચક્કર ૨૦ms સુધી રાહ; GUI ને દર **0.1 સેકન્ડ** snapshot |
| thread | engine **અલગ thread** માં — GUI અટકે નહીં |

### મર્યાદા

- **રીઅલ-ટાઈમ નથી.** UDP packet ખોવાય તો તે ચક્કર જતું રહે (next મીટરે સુધરે).
- મીટર દર ~50ms આવે, એટલે `attack_time` ૦.૦૨ કરતાં પણ **વાસ્તવમાં એક
  મીટર-ચક્કર** જેટલો વિલંબ રહે.
- એક સમયે **એક જ મિક્સર**.
- Windows/PC બંધ થાય તો automation બંધ — **મિક્સર જેમ છે તેમ ચાલુ રહે**
  (જે હાલતમાં છોડ્યું હોય તે).
