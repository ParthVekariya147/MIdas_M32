# 10 — Fader / Mute ધ્યાનમાં લેવું

## પ્રોબ્લેમ (અસલી બગ, ૨૬-૦૮-૨૦૨૬ પકડાયો)

ચેનલ ૧૦ નો **fader સાવ નીચે** (−∞) હતો, છતાં automation ઇફેક્ટ ચાલુ
કરી દેતું હતું. પણ એ ચેનલનો અવાજ તો મિક્સમાં જતો જ નથી — એટલે
ઇફેક્ટ ચાલુ થવી ના જોઈએ.

## કારણ

આપણે **bank 0** નું મીટર વાંચીએ છીએ, જે **pre-fader** છે.

```
માઈક  →  preamp  →  [મીટર અહીં વંચાય]  →  fader  →  mix
                     ↑ અહીં અવાજ દેખાય    ↑ અહીં બંધ થઈ જાય
```

માઈકમાં અવાજ આવે એટલે મીટર હલે, ભલે fader નીચે હોય.

## ઉકેલ

મિક્સર પાસેથી **fader ની હાલત પણ પૂછવી**, અને જાતે ગણતરીમાં લેવી:

```
ખરો_લેવલ (dB) = મીટર (dB) + fader (dB) + DCA fader (dB)
```

અને આમાંથી કોઈ પણ હોય તો એ ચેનલ **સાવ ગણવી જ નહીં**:

| સ્થિતિ | OSC path |
|---|---|
| ચેનલ mute છે | `/ch/XX/mix/on` = 0 |
| જે mute group માં છે તે ચાલુ છે | `/ch/XX/grp/mute` + `/config/mute/N` |
| જે DCA માં છે તે બંધ છે | `/ch/XX/grp/dca` + `/dca/N/on` |

## Fader → dB (મિક્સરની પોતાની ગણતરી)

| fader value | dB |
|---|---|
| 1.00 | +10 |
| **0.75** | **0** (unity — fader સીધો ઊંચો) |
| 0.50 | −10 |
| 0.25 | −30 |
| 0.0625 | −60 |
| 0.00 | −90 (−∞, સાવ નીચે) |

કોડ: `m32_core.py` → `fader_to_db()`

## "fader પ્રમાણે ઇફેક્ટ જવી જોઈએ" — હા, એમ જ થાય છે

fader અડધો હોય (−10 dB) તો ખરો લેવલ પણ −10 dB ઓછો ગણાય.
એટલે **fader જેમ નીચે જાય તેમ ઇફેક્ટ ચાલુ થવાનું ઓછું થતું જાય** —
અને સાવ નીચે જાય એટલે બિલકુલ બંધ.

દા.ત. threshold −40 dB હોય અને માઈકનો અવાજ −8 dB:

| fader | ખરો લેવલ | ઇફેક્ટ |
|---|---|---|
| 0 dB (unity) | −8 | ચાલુ ✅ |
| −10 dB | −18 | ચાલુ ✅ |
| −30 dB | −38 | ચાલુ ✅ (હજી threshold ઉપર) |
| −50 dB | −58 | બંધ ❌ |
| −∞ | −∞ | બંધ ❌ |

## ⚠️ Race condition (આ પણ સાથે ફિક્સ થયો)

પ્રોગ્રામ ચાલુ થાય ત્યારે fader ની ખબર હોતી નથી. ત્યાં સુધી
"unity છે" એમ માની લઈએ તો **પહેલી અડધી સેકન્ડમાં ખોટું ચાલુ થઈ જાય**.

**ફિક્સ:** જ્યાં સુધી મિક્સર fader ની ખબર ના આપે ત્યાં સુધી એ ચેનલ
**"બંધ છે" એમ માનવું**. મિક્સર ૪ સેકન્ડમાં જવાબ ના આપે (જૂનું
firmware) તો warning લખીને જૂની રીતે ચાલુ રાખવું.

કોડ: `m32_engine.py` → `_state_ready`, `_state_gaveup`

## માહિતી ક્યારે વંચાય છે

| ક્યારે | શું |
|---|---|
| જોડાતાં જ | બધી ૩૨ ચેનલ + DCA + mute group |
| દર ૨ સેકન્ડે | પસંદ કરેલી ચેનલ + DCA + mute group |
| દર ૧૫ સેકન્ડે | બધી ૩૨ ચેનલ (GUI બતાવવા) |
| તરત | `/xremote` — મિક્સર જાતે પણ મોકલે છે |

## GUI માં ક્યાં દેખાય

દરેક ચેનલની જમણી બાજુ **FADER** ખાનું:

| દેખાય | અર્થ |
|---|---|
| `+0.0` | fader unity — પૂરો અવાજ |
| `-10.5` | fader એટલો નીચો (પીળું) |
| `-oo` | fader સાવ નીચે (લાલ) |
| `MUTE` | ચેનલ/DCA/mute group બંધ (લાલ) |

લેવલ બાર પણ હવે **ખરો લેવલ** બતાવે છે (fader લગાવ્યા પછીનો).

## Toggle

**"Fader / Mute dhyanma lo"** — default ચાલુ.

બંધ કરો તો જૂની રીતે ચાલે (ફક્ત મીટર જુએ, fader ના જુએ).
કોઈ કારણસર fader વાંચવામાં વાંધો આવે તો જ બંધ કરવું.

## કોડ ક્યાં છે

| શું | ફાઈલ |
|---|---|
| fader → dB | `m32_core.py` → `fader_to_db()` |
| ખરો gain ગણવો | `m32_engine.py` → `channel_gain_db()` |
| GUI માટે લખાણ | `m32_engine.py` → `channel_state_text()` |
| મિક્સરને પૂછવું | `m32_engine.py` → `_poll_channel_state()`, `_poll_groups()` |
| જવાબ વાંચવો | `m32_engine.py` → `_on_packet()` |
| GUI માં બતાવવું | `m32_gui.py` → `_apply_status()` |

## શું બગડી શકે

| લક્ષણ | ઉપાય |
|---|---|
| બધી ચેનલ `MUTE` દેખાય | મિક્સર fader ની ખબર નથી આપતું — ૪ સેકન્ડ રાહ જુઓ, warning આવશે |
| fader ઊંચો છતાં ચાલુ ના થાય | DCA બંધ છે? mute group ચાલુ છે? FADER ખાનું જુઓ |
| fader બદલો પણ તરત અસર ના થાય | વધુમાં વધુ ૨ સેકન્ડ લાગે (`/xremote` હોય તો તરત) |
| જૂનું firmware | toggle બંધ કરીને જૂની રીતે ચલાવો |
